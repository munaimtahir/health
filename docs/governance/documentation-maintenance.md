# Documentation Maintenance

Status: Canonical. Purpose: define how documentation stays aligned with implementation.

Every feature or architecture change updates its related canonical document, acceptance criteria, and decision record when applicable. Use relative links and verify them before review. Never edit archived source to make it appear current. New contradictions are logged with context, options, decision owner, and date. At sprint close, compare the module tree, permissions, dependencies, user-facing strings, and quality-gate results against the canonical docs.
