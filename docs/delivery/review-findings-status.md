# Review findings status

Tracks the status of findings from the pasted external "Health-Passport-Review" master fix prompt against the actual repository state, verified by direct code inspection (not assumed from the prompt's premises). `Health-Passport-Review.md` itself is not present in this repository; findings below are the prompt's own claims, checked against HEAD.

| Finding | Status | Notes |
|---|---|---|
| Application ID mismatch (`pk.vexel.healthpassport` vs `com.vexel.passport`) | NOT REPRODUCIBLE | `app/build.gradle.kts` confirms `applicationId = "com.vexel.passport"`, matching `CLAUDE.md`. No trace of the old ID in the current tree. |
| Gradle wrapper present and working | CONFIRMED (now fixed) | `gradlew`/`gradlew.bat`/`gradle-wrapper.jar` were absent from git; `./verify_project.sh` failed at the first stage. Regenerated via `gradle wrapper --gradle-version 8.13` and committed. See `docs/delivery/quality-gate-results.md`. |
| Feature modules (`feature/*`) are placeholder scaffolding, not real | CONFIRMED | All `feature/*/src/main/kotlin` files are 5-line `/** X feature placeholder. */` stubs (55 lines total across all 11 modules). Matches `CLAUDE.md`'s own stated current state. |
| Single God ViewModel + monolithic app-shell file | CONFIRMED | `app/src/main/kotlin/com/vexel/passport/VexelHealthPassportApp.kt` (1032 lines) contains `PassportViewModel` plus every screen composable. No `core:data` module exists; the ViewModel talks to `HealthDatabase` directly, bypassing the (unused) `core:domain.HealthRepository` contract. |
| Duplicate Room database instance during reminder reconciliation | CONFIRMED (now fixed) | `WorkManagerReminderScheduler.reconcile()` called `DatabaseProvider.create(context)` to build a second `HealthDatabase` instance alongside the Hilt-provided singleton, on every app start. Fixed by injecting the singleton `HealthDatabase` into the scheduler instead. `ReminderWorker.doWork()` still creates its own instance — left as-is: it runs inside a WorkManager background execution that is not guaranteed to share the app process's DI graph, and this is a materially different (and more defensible) case than the ViewModel-lifecycle duplication the review flagged. |
| Navigation is a `remember { selectedIndex }` switch, not a real `NavHost`/`NavController` | CONFIRMED (now fixed) | Replaced with `NavHost` + `NavController` using centralized string routes (`Routes.HOME/RECORDS/PLAN/VAULT/PROFILE`) and the standard single-top/save-state bottom-nav pattern. Typed `@Serializable` routes were not introduced because `kotlinx-serialization` is not currently a project dependency, and the instructions explicitly say not to leave a partially configured typed-navigation setup. |
| "Records vs Vault" / "Timeline vs Plan" naming mismatch | ALREADY RESOLVED | The five destinations are already named `Home, Records, Plan, Vault, Profile` consistently across the bottom nav, the `NavigationAccessibilityTest`, and (now) the route table. No further decision needed. |
| App is a "spec-only pack" / not runnable | NOT REPRODUCIBLE | The app is a real, working MVP: Room (8 migrations), DataStore, Keystore-backed PIN material cipher, PBKDF2+AES-GCM encrypted backup/restore with transactional rollback, WorkManager reminders, PDF export, and a document vault, all covered by existing unit and instrumented tests. `docs/delivery/final-build-report.md` records sprints 0–12 passing internal-testing gates on a physical device in a prior session. |
| ViewModel methods take Android `Context` directly | CONFIRMED, not yet fixed | `PassportViewModel` has ~11 methods taking `Context` (document import/open/share/replace, PDF export, backup/restore, symptom image attach). Deferred — see `docs/delivery/deferred-owner-decisions.md`; fixing this safely requires introducing an application-scoped file/URI service and touches the same surface as the encrypted-backup and document-vault code paths, which are the app's highest-consequence (data-loss-risk) code. |
| Long-form CRUD trapped in `AlertDialog`s (symptom/medication/reminder/document capture) | CONFIRMED, not yet fixed | 15 `AlertDialog(...)` call sites in `VexelHealthPassportApp.kt`. Deferred — UX/Phase 3 scope. |
| No Paging3 / unbounded list loading for timeline | CONFIRMED, not yet fixed | `events`/`documents`/etc. are loaded as full `StateFlow<List<...>>` from Room with no `PagingSource`. `LargeDataPerformanceTest` exercises a 10,000-row dataset already, so this is a real but bounded risk, not an unverified one. Deferred — Phase 2 scope. |
| Raw exceptions crash the app instead of showing a safe error | CONFIRMED (now fixed) | `createBackup`/`restoreBackup`/`createPdfReport`/`importDocument`/`replaceDocument` all ran inside unguarded `viewModelScope.launch` coroutines. A wrong backup password (`AEADBadTagException`), a corrupted backup, or an oversized/unsupported document import (`IllegalArgumentException` from `SecureFileStore`'s `require()` calls) was an uncaught exception — an app crash, not a UI-visible error. Fixed by wrapping each with try/catch producing a generic `operationError` message (never the raw exception, never health data), shown via a shared `AlertDialog` at the app-shell level; success is confirmed via `Snackbar`. Covered by `BackupRestoreTest.wrong_password_...` and the new `DocumentImportErrorTest` (instrumented; compiled but not executed in this environment — no device attached). |
| Medication start/stop dates have the same length-only-validation gap as symptom dates | CONFIRMED (now fixed) | `MedicationDraft.validationErrors()` had the identical defect to the symptom-date one above. Fixed with the same strict `java.time` parser pattern. |
| Tautological application-ID test | CONFIRMED (now fixed) | `AppShellTest.applicationIdentityIsFixed()` compared `"com.vexel.passport"` to itself. Replaced with real assertions on `primaryDestinationLabels`/`Routes`, the actual contract introduced by the NavHost refactor. |
| No screenshot/recent-apps privacy protection | CONFIRMED (now fixed, opt-in) | Added `hideRecentAppsPreview` preference (default off) + `FLAG_SECURE` wiring + a Profile-screen toggle. Default-value tradeoff recorded as DOD-004 in `deferred-owner-decisions.md`. |
